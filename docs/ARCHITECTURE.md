# Architecture and recovery

`Game` is a deterministic, bounded Java simulation. The UI owns its state and drives it with monotonic elapsed time at ~30Hz, or ~10Hz in reduced-motion mode. Each update caps delta to 100ms; there is no wall-clock catch-up. PRNG state, active enemies, crop growth, cooldowns, settings and progression are all persisted. Rendering reads state; it never mutates rules. Native button panels supply all actions; Canvas artwork is excluded from accessibility traversal to avoid duplicate controls.

`FarmApp` holds one in-process farm and one sequential save writer across Activity recreation. Rotation reuses current state instead of racing another writer or loading a partially pending checkpoint. Activity instance state retains the selected tab and seed; reopening still requires Play. Bulk planting derives its budget/count from current coins and empty unlocked plots, debits one seed at a time through the existing rule, and never replaces crops. Countdown estimates use the same growth-rate function as simulation. No persistent fields or save-schema changes were added in rc.2. The single-task launcher prevents parallel farm windows. `MainActivity` owns lifecycle, pause/foreground flags, native controls and SAF backup picker. State is paused on focus loss and always starts paused on resume. Welcome explicitly starts the initial game. Dialogs pause time. Font sizes use sp and controls are in a ScrollView; visual scene scales independently. Buttons do not require fast repeated aiming. No audio/vibration/flashing effects. Reduced motion removes rain travel, enemy bob and shot tracer flashes and reduces drawing frequency.

`SaveCodec` uses binary magic BTFS, schema 1, revision number, fixed bounded fields, at most 45 enemies and a CRC32 trailer. Maximum accepted backup 16KiB. CRC detects accidental corruption; it is not encryption/authentication. Validate size, format, all ranges, finite floats, counts, and checksum before replacing state. Saves are not trusted multiplayer/economy authority. No personal data is collected.

`SaveStore` snapshots on mutations, every three active seconds and when backgrounding. A single worker coalesces pending snapshots and alternates two Android AtomicFile slots after successful writes, independent of skipped revision numbers. Each slot is atomically committed; startup chooses the highest valid revision. If one slot fails validation, the other is restored with visible notice. If both are invalid, automatic writes and play are blocked until explicit reset/import. Failed writes leave play available and show an export-backup warning. Normal sudden process death can lose up to the latest checkpoint interval plus pending IO; no claim of durability before a successful write callback. The application-scoped writer accepts already queued writes across Activity destruction. No disk work in the frame callback beyond in-memory encoding and queuing. Startup reads at most two 16KiB saves.

Import/export runs on a separate serial worker using Android's document picker; it requests no broad storage permission. Import confirmation precedes file selection, and validation precedes state replacement. A pending import disables state actions and simulation. Import/new-farm revisions advance from the existing revision so older queued snapshots cannot win on restart. No external URI is logged. The file provider may itself be cloud-backed; use on-device storage for offline backups.

Limits: one local farm; no offline advancement; no schema migration needed for first release; no synchronization across devices. No physical equipment control, external signal path or HIL authority rules apply. Real handset rendering, lifecycle and accessibility still require device acceptance.

References used for lifecycle decisions: Android Developers [Activity lifecycle](https://developer.android.com/guide/components/activities/activity-lifecycle). Background saving is asynchronous; onPause stops the loop immediately.

Lint policy: all warnings remain errors. Narrow intentional exceptions are documented in source: English-only dynamic UI text in `refresh` (localization outside MVP), programmatic FarmView constructor injection (no XML inflation), and target SDK35 instead of latest SDK (pinned/verified toolchain, no Play Store submission). Default-locale conversion, API26 navigation styling, Android12 data extraction and per-frame gradient allocations are corrected rather than suppressed. No baseline file hides findings.

Lifecycle interruption handling: `onWindowFocusChanged(false)` pauses and checkpoints active play, including system overlays that do not trigger `onPause`. Focus return never starts simulation. Instrumentation separately dispatches focus callbacks and executes a real Home/foreground round trip. Shell stdout is drained before closing its descriptor, then UI state is observed on the main thread with a 10-second deadline rather than assuming a 500ms transition. See Android [UiAutomation.executeShellCommand](https://developer.android.com/reference/android/app/UiAutomation#executeShellCommand(java.lang.String)).

## In-world interface (0.2)

`GameBoard` lays native `GameButton` plot/lane controls over `FarmView`. Both consume one `BoardGeometry` instance, recalculated on measure using screen orientation/density. Geometry determines artwork and actual view bounds, not a separate approximate hit-test. All input remains native: touch, keyboard focus and accessibility share the same actions. `CropIcon` provides original vector seed illustrations; selected/ready/locked states also have text/labels. Button skins reuse drawable objects and native ripple feedback. No extra runtime library or bitmap asset is required.

The compact HUD, seed tray, board, notice and action dock form one immersive window. A fill-viewport ScrollView allows content to expand at large fonts/short screens; the world has a minimum height derived from48dp cells and font scale. Cutout/caption insets protect controls; system bars can be revealed by edge swipe. The paused upgrade overlay consumes touch, hides the underlying board from accessibility traversal and restores its traversal when closed. Back closes upgrades first. Seed and overlay state survive recreation. Start night is an explicit resume action; closing upgrades/rebuilding are not. Economy/combat and schema1 are unchanged except lane display names now match top/middle/bottom.
